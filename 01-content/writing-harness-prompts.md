# Writing harness — proposed instructions

**Draft instructions for the system we are designing.** No writing automation is running. Drew requested Sonnet for both writing stages; its exact provider model ID remains to be verified.

## Inputs prepared before writing

- **Audience:** homeowners; educational pest-control shorts for Deep Six.
- **Resource card:** source ID/link, lesson ID, pest/species/region, supported facts with source locations, practical takeaway, limits and previous-use status.
- **Hook studies:** original video links, short opening excerpts/timestamps, observed visuals, opening patterns, available metric snapshots, and evidence limits.
- **Feedback:** concise notes on what Drew liked or rejected. Do not include archived rejected narration bodies.
- **Constraints:** brand tone, target duration once chosen, current batch ID and source grouping from Q1. Do not guess an unresolved grouping.

## Stage 1 — make five hook choices

> Write exactly five original spoken hooks for the supplied homeowner lessons. Each hook must identify its lesson and factual source. Follow the supplied source grouping; do not silently switch articles.
>
> Use the hook studies to understand opening structures, specificity and pacing. Get every pest claim from the resource card. A social video’s claim or view count is not factual support for our lesson. Do not copy another creator’s wording, invent numbers, manufacture urgency, or promise a result the article does not support.
>
> Make the choices meaningfully different. Each should lead to one useful lesson we can show with cartoon action. Reject a hook whose promised payoff is missing from the source.
>
> Return five numbered choices. Display the hook and a brief plain-English lesson label, with a source link. Keep the source ID, supporting fact IDs and hook-study references in metadata. Check count, originality, supported promise and duplicate lesson use before display.
>
> Wait for a human choice. Skip replaces the current batch with five new choices and uses the rejection feedback. Do not automatically select a winner. A second selected hook is queued, not combined with the current hook.

## Stage 2 — make five narration choices

> Write exactly five complete voiceover scripts using the supplied selected hook and its same factual source. Print the exact selected hook as the first spoken line of every script. Show the entire script under each number; never replace the hook with “same hook.”
>
> All five scripts must deliver the selected hook’s promised lesson. Vary the explanation, order, rhythm or way of illustrating the point; do not produce five synonym swaps. Keep facts and limits consistent across all versions.
>
> Talk to one homeowner in ordinary spoken English. Explain why an action matters before recommending it. Use connected thoughts and concrete things the viewer can see. Do not invent a personal/customer story, add unrelated tips, force jokes, or repeat a sales ending; the branded outro is handled separately.
>
> Use only the supplied source-supported facts. Put citations and claim-to-source checks outside the spoken script. If the selected hook itself lacks support, flag that problem instead of silently changing it.
>
> Check that all five hooks match exactly, each script is complete, every pest claim is supported, and the options are genuinely different. Mark duration as an estimate until an actual spoken read exists.
>
> Wait for Drew to choose one or Skip. Skip generates another five with the same selected hook and resource. On replacement, discard the previous narration text; retain only the prompt/settings, IDs, source-use metadata, checks and concise feedback. Once one is chosen, keep that script and remove rejected narration text.
